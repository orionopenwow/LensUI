# Lens Apps

A curated catalogue of free and open-source tools with one-click install, live thumbnails, a detail page, reversible setup recipes, and voice/menu/AI hooks. Research, sources and the safety model are in [APPS_RESEARCH.md](APPS_RESEARCH.md).

Everything is off until opened, and nothing installs without a click.

## How it looks and behaves

- **Home shows each app once.** Sections, in order:
  - Open-source rewrites;
  - the ArtCraft suite as one compact row (the launcher plus app icons);
  - AI on your PC;
  - Essentials;
  - a "Browse by category" grid. Category tiles and chips filter the list instead of repeating rails.
- **Real media.** Icons and screenshots come from each project's own GitHub repo, pinned to a commit, as `raw.githubusercontent.com` URLs.
  - The URLs are found and checked by `tools/apps/fetch_media.py`. That script makes blob-less shallow clones, picks the icon and the README or screenshot images, and records `tools/apps/media.json`. Hand-checked choices live in `tools/apps/media_sources.py`.
  - Nothing is committed except the URLs.
  - 44 of 51 apps have an icon and 26 have screenshots. The rest carry a `noMedia` reason (closed source, or screenshots only on the project's website), and the tests require one or the other.
  - Installed apps prefer the icon extracted from their own program file (`apps_installed_icon`).
- **Media loading in Lens.**
  - `apps_media(appId, url)` downloads only URLs listed in that app's entry, over HTTPS, with same-host redirects only.
  - It checks per-type size caps and the file's magic number, and refuses SVGs that contain scripts, event handlers or external references.
  - Files are cached as `%APPDATA%\LensUI\apps\media\<sha256(url)>.<ext>`, least-recently-used, with a 300 MB cap.
  - The page shows them through the asset protocol, so the window's CSP never loads remote images.
  - While loading there's a shimmer. If there are no screenshots, or one fails, the app's icon sits on a backdrop tinted from its id; if there's no icon, a category glyph is shown, never letters.
- **One click.** Each card has an App Store-style pill:
  - **Get** becomes a progress ring (tap to cancel), then **Open**.
  - **Update** appears when one is available; **Run** appears for a verified release download.
  - **⋯** opens Details, Show in folder and Uninstall.
  - The single confirmation is a compact popover anchored to the pill. It shows the source, licence, size and "via winget" or "GitHub release". For winget, that popover is the only confirmation.
  - GitHub releases download and verify in the queue, then ask once more in the same popover ("GitHub release, verified": checksum and signature) before running.
- **Queue and tray.** Several Gets queue and run one at a time, and a download tray in the window's corner shows progress. After an install, the tray shows a short setup checklist (Dock pin, "Open in…", voice phrases, Guide lesson) with sensible defaults ticked; switching Lens AI's model provider stays unticked. It never blocks browsing.
- **Keyboard.** `/` searches, Enter on a card opens details, Ctrl+Enter on a card is Get, Esc closes the popover and then goes back, and the arrow keys move along a row.

## Commands and events

| Command | What it does |
|---|---|
| `apps_catalog` | The bundled catalogue. |
| `apps_catalog_refresh` | Disabled until signed catalogues land; returns a plain message. |
| `apps_settings_get` / `apps_settings_set` | `{autoUpdate: false, checkUpdates: "weekly", showNonOpenSource: true, liveThumbnails: true}` |
| `apps_installed` | One `winget list`, giving installed and available versions of catalogue apps. |
| `apps_lens_installed` | Ids Lens installed. |
| `apps_audit` | The audit log. |
| `apps_show` | `winget show`: version, publisher, licence and agreements, shown before Install. |
| `apps_run(appId, op)` | `install` \| `upgrade` \| `uninstall` through winget. Returns a job id. |
| `apps_cancel(jobId)` | Cancels a running job. |
| `apps_release_prepare(appId)` | Downloads, checks the checksum and signature, and returns what the second confirmation shows. |
| `apps_release_run(token)` | Re-hashes, then runs the installer. |
| `apps_release_discard(token)` | Deletes a prepared download. |
| `apps_open(appId)` | Web URL, or the matching Start-menu shortcut. |
| `apps_open_link(appId, url)` | Only URLs present in that app's entry. |
| `apps_recipe_preview` / `apps_recipe_apply(appId, chosen)` / `apps_recipe_revert` | Setup recipes. |
| `apps_media(appId, url)` | Cached local path for one of the app's official media URLs. |
| `apps_installed_icon(appId)` | PNG data URL of the installed app's own icon. |
| `apps_reveal(appId)` | Shows the installed program file in File Explorer. |
| `apps_integrations` | Current recipe-written integration state. |

**Events:**
- `lens://apps/progress {jobId, appId, op, stage, pct, message}`, where `stage` is `resolving` → `downloading` → `verifying` → `installing` → `done` or `failed`.
- `lens://apps/integrations` carries the full integration state after a recipe change.

### §3 Voice and Command (voice package / `src/command/*`)

```ts
import { parseAppsIntent, describeIntent } from "../apps/intents";
const intent = parseAppsIntent(transcriptOrCommandText, catalog, new Set(Object.keys(installed)));
if (intent) switch (intent.kind) {
  case "install": case "uninstall":  // risk "confirm": open the Apps window on the app with the sheet
    openAppsWindow({ app: intent.app?.id, sheet: intent.kind }); break;
  case "open": intent.app && invoke("apps_open", { appId: intent.app.id }); break;
  case "updateAll": showApproval({ title: "Update all apps Lens installed?", onApprove: updateAll }); break; // confirm
  case "describe": case "recommend": speakAndShow(describeIntent(intent)); break;
  case "openApps": openAppsWindow({ q: intent.query }); break;
}
```

Phrases covered by tests:
- "Lens, install ArtCraft"
- "open the charting app"
- "update all my apps"
- "what does Concat do"
- "what should I use for slides"
- `/apps video`
- `/install concat`

Installs and uninstalls are confirm-risk: the sheet is the approval card.

### §4 Right-click catalogue (`src/context/actions.ts`, feature/rightclick-context)

Read `apps_integrations().openWith` (app id → extensions). For a file whose extension matches, add `{ id: "open_in_app", label: "Open in <App name>", run: () => invoke("apps_open", { appId }) }`. The magic right-click window uses the same list under "Open with…". Listen to `lens://apps/integrations` to refresh.

### §5 Dock (`DockSurface.tsx` / config)

On `lens://apps/integrations`, add any new `dock` ids as pins using the Start-menu shortcut Lens finds for that app (the `apps_open` lookup). On revert, remove only pins the recipe added (the event carries the full list).

### §6 Lens AI (feature/ai-core)

When `integrations.localProvider` is `"ollama"` or `"lmstudio"`, call `ai_set_config` with that provider as the local engine, restoring the previous value on revert. The MCP entries in `integrations.mcp` go into the MCP client list with per-tool approval.

### §7 Guide (feature/lens-guide)

Index `catalog.json` (name, pitch, why, category, replaces) so "what tool should I use for slides?" answers from the catalogue. The ready-made logic is `parseAppsIntent` → `recommend`. Lesson stubs come from `integrations.guide`.

### §8 Backup and uninstall (`win_backup.rs`, `win_uninstall.rs`)

- Include `%APPDATA%\LensUI\apps\{settings,integrations,journals,installed}.json` in backups.
- "Remove all Lens changes" should call `apps_recipe_revert` for each id in `journals.json`.
- "Remove all Lens changes" does **not** uninstall apps; that is a separate, explicit button in AppsCard.

## Editing the catalogue

1. Edit the table in `tools/apps/make_catalog.py`.
2. Run `python3 tools/apps/make_catalog.py`.
3. Run `bun test src/__tests__/apps.test.ts`. The schema tests check every https URL, licence, winget id and recipe step.
4. Optionally run `rustc --edition 2021 --test src-tauri/src/apps/mod.rs`, which checks the backend accepts every install spec.
