## 1. Top 5 ideas to build

### 1. Lock dependencies and audit them in CI (recurring, now with fresh advisories)
- **Evidence:** rustls releases before 0.23.46 have five new CVEs, published 8 Nov; hickory-dns before 0.26.2 has 39 CVEs, including DNSSEC bypasses ([Corgea, 12 Nov](https://corgea.com/research/cve-2026-122302-122321-123595-123613-rustsec-2026-0446-kyverno-hickory-dns-actix-rustls-november-2026)). Yesterday's note also listed the Tauri and rustls-webpki advisories ([note](./2026-11-23.md)).
- **Why it matters:** `reqwest` with `rustls-tls` pulls rustls into every Claude and local-model call. `src-tauri/Cargo.lock` has no `rustls` entry at all, and it resolves `reqwest 0.13.5` while `Cargo.toml` asks for `0.12`. So CI resolves fresh versions on each build (`build.yml:77`, no `--locked`), and nobody can say which rustls a release shipped.
- **Lens status:** **Missing.** There is still no `--locked` and no `cargo audit` / `cargo deny` step (checked `.github/workflows/build.yml`).
- **Effort / risk:** S / low. Needs one Windows build to regenerate the lockfile.
- **Files likely touched:** `src-tauri/Cargo.lock`, `.github/workflows/build.yml`, new `src-tauri/deny.toml` (optional).

### 2. "Moving from Arc" in Lens Browser before Arc shuts down on 22 December
- **Evidence:** Zen 1.24.1b (6 Nov) imports Arc and Dia spaces and profiles, and reports that Arc shuts down on 22 Dec 2026 ([LinuxCompatible](https://www.linuxcompatible.org/story/zen-browser-1241b-release-closes-security-hole-as-arc-faces-sunset/), [PiunikaWeb, 30 Oct](https://piunikaweb.com/2026/10/30/zen-browser-adds-arc-and-dia-import-shareable-boosts-firefox-v159/)). The shutdown date was not checked against The Browser Company's own site.
- **Why it matters:** Arc users on Windows have a deadline. They will be looking for a new browser in the next four weeks, and Lens Browser already covers most of what they need.
- **Lens status:** **Partial.** Arc import with spaces already exists (`src/browser/ImportPanel.tsx`, `src-tauri/src/browser/import/`). There is no Dia source. It is unverified whether Dia has a Windows build. Nothing in the app, the README or the site tells Arc users that Lens can take their spaces.
- **Effort / risk:** S / low. Most of the work is copy: an Import-panel banner when an Arc profile is detected, plus a README and site line. Add Dia only if it turns out to have a Windows profile folder.
- **Files likely touched:** `src/browser/ImportPanel.tsx`, `src-tauri/src/browser/import/*`, `docs/LENS_BROWSER.md`, `README.md`, the site's browser section.

### 3. A different wallpaper on each monitor
- **Evidence:** Lively's latest notes add per-display pausing and per-display audio ([Lively changelog](https://rocksdanister.com/lively/changelog); the version and date did not come through on the page). Wallpaper Engine has had per-monitor wallpapers for years.
- **Why it matters:** Multi-monitor users are the core audience for customisers. Lens's new Wallpaper Switcher (PR #65) is good, but it fills only one screen.
- **Lens status:** **Partial.** `WallpaperSettings` in `src-tauri/src/win_wallpaper.rs` has one `file` / `scene`. The host attaches to a single monitor rect (`attach_wallpaper_window`, `MONITOR_DEFAULTTOPRIMARY`). Pause-when-covered and battery pausing already exist, and so do per-workspace scenes (`workspace_scenes`). Nothing is keyed per monitor.
- **Effort / risk:** M / medium. Needs one host window per monitor, per-monitor pause, and a monitor picker in the Switcher. Each extra video or HTML wallpaper adds GPU cost.
- **Files likely touched:** `src-tauri/src/win_wallpaper.rs`, `src-tauri/src/wallpapers/mod.rs`, `src-tauri/src/commands/wallpapers.rs`, `src/wallpapers/{model.ts,WallpaperPicker.tsx,SwitcherCard.tsx}`, `src/surfaces/WallpaperSurface.tsx`, `src/types/generated.ts`.

### 4. "Refraction" glass material for the Dock and Top Bar
- **Evidence:** Blur my Shell v76 (18 Oct) updates its Liquid Glass shader and adds a refraction slider ([releases](https://www.github.com/aunetx/blur-my-shell/releases)). Hyprland 0.57 (28 Oct) ships swappable blur variants and proportional blur ([LinuxCompatible](https://www.linuxcompatible.org/story/hyprland-0571-releases-stability-patch-fixing-nvidia-black-screens-and-keybindings/)).
- **Why it matters:** Refraction glass is the look people are chasing in late-2026 setups, on Linux and on Apple-inspired themes. Lens draws its own Dock and Top Bar in WebView2, so it can offer the look without touching DWM.
- **Lens status:** **Missing.** There is glass and blur in the theme packs, but no refraction or displacement material. The only `refract` hits are in scenes and the Backdrop Lab.
- **Effort / risk:** M / medium. It can be done as an SVG displacement filter over `backdrop-filter`. GPU cost must stay inside the smoothness budgets (`docs/SMOOTHNESS.md`), and the effect must turn itself off in battery saver and Calm mode.
- **Files likely touched:** `src/style/` (new `glass.css` / `glass.ts`), `src/surfaces/DockSurface.css`, `src/surfaces/TopBarSurface.css`, `src/themes/featured.ts` (one featured look uses it), theme schema in `src/themes/lenstheme.ts`.

### 5. Separate styling for inactive windows: border colour and shadow strength
- **Evidence:** Klassy 6.7 gives active and inactive windows separate shadows ([KDE Discuss](https://discuss.kde.org/t/klassy-theming-utility-v-6-7-1-released/49532), Aug 2026; older than a week, but it is the newest Klassy release). Window-border colour and size how-tos keep circulating ([Windows Report](https://windowsreport.com/windows-11-change-window-border/)).
- **Why it matters:** Lens already dims inactive windows and rings the active one. A muted border on inactive windows completes the "which window has focus" story, and DWM can do it cheaply.
- **Lens status:** **Partial.** `win_focus_dim.rs` handles the active ring and dimming, and `win_rules.rs` has `inactive_opacity`. `win_dwm_engine.rs` (`style_hwnd`) writes one `DWMWA_BORDER_COLOR` for every styled window, whatever its focus state. There is no separate inactive colour.
- **Effort / risk:** S / low. Re-apply the border colour on focus change, from WinEvent hooks Lens already has. `release_hwnd` already resets the border to the default, so Remove all is covered. Check that `changes.rs` still lists it.
- **Files likely touched:** `src-tauri/src/win_dwm_engine.rs`, `src-tauri/src/win_focus_dim.rs`, `src-tauri/src/win_rules.rs`, `src-tauri/src/changes.rs`, the Window styling card in Settings.
