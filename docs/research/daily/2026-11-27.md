## 1. Top 5 ideas to build

### 1. HDR-safe Snip capture
- **Evidence:**
  - ShareX 22.4.0 (8 Nov) added HDR tone mapping because recordings on HDR monitors came out washed out ([tutkit](https://www.tutkit.com/en/news/1010-sharex-2240-captures-hdr-screens-with-tone-mapping)).
  - The same release added an HEVC fallback for areas too big for H.264.
- **Why it matters:** HDR laptops and monitors are now common.
  - Lens Snip captures through GDI: `BitBlt` with `CAPTUREBLT` and `PrintWindow` (`src-tauri/src/snip/win.rs:5`).
  - Recording uses ffmpeg `gdigrab` (`record.rs:1`).
  - Neither path tone-maps, so HDR desktops may produce dim or washed-out snips. This is **not verified on hardware**: Lens has no HDR test.
- **Lens status:** **Missing.** `snip/` has no HDR, SDR or advanced-colour handling.
- **Effort / risk:** M / medium.
  - First, detect HDR per monitor with `DisplayConfigGetDeviceInfo` (advanced colour) and warn in Snip.
  - Then add a Windows.Graphics.Capture path with an FP16 → SDR tone map. This joins backlog #21, Snip recording via Windows.Graphics.Capture.
- **Files likely touched:** `src-tauri/src/snip/win.rs`, `src-tauri/src/snip/image.rs`, `src-tauri/src/snip/record.rs`, `src-tauri/src/snip/geom.rs`, `docs/SNIP.md`.

### 2. Say a caption while you snip: hold Space during the drag, speak, then paste image and text together
- **Evidence:**
  - PowerToys 0.102 added ZoomIt "snip dictation": hold Space while dragging a snip and speak. One paste then delivers the image plus text transcribed on the device ([ElevenForum](https://www.elevenforum.com/t/new-microsoft-powertoys-version-0-102-2933-0-for-windows-11.50296/); the release date isn't on the page).
- **Why it matters:** Lens already has both halves: whisper.cpp voice (`src-tauri/src/voice/`) and Snip with Shelf and Copy. A spoken caption turns a snip into a bug report, a note or a Claude prompt in one gesture, with nothing sent to the cloud.
- **Lens status:** **Missing** (the parts exist). No dictation code in `snip/`. Voice has hold-to-talk in `voice/hold.rs`.
- **Effort / risk:** M / medium.
  - Space is already a key in the Select overlay, so check `src/snip/keys.ts`.
  - Only run it when Voice is set up, and show the mic state clearly.
- **Files likely touched:** `src/snip/Select.tsx`, `src/snip/keys.ts`, `src/snip/api.ts`, `src-tauri/src/snip/service.rs`, `src-tauri/src/voice/hold.rs`, `src-tauri/src/shelf/*` (store the caption with the clip).

### 3. A Snip reliability pass: mixed DPI, monitors left of or above the main one, and overlay cost
- **Evidence:** ShareX 22's rewrite brought a run of regressions, 14–23 Nov:
  - [region capture drops the desktop frame rate](https://github.com/ShareX/ShareX/issues/9343) (23 Nov, 7 comments);
  - [it breaks with DPI scaling](https://github.com/ShareX/ShareX/issues/9297) (18 Nov, 5);
  - [multi-screen region selection](https://github.com/ShareX/ShareX/issues/9306) (19 Nov, 4);
  - [huge VRAM use](https://github.com/ShareX/ShareX/issues/9273) (16 Nov, 3).
  - Also: PowerToys 0.102 fixed Crop And Lock alignment on scaled displays.
- **Why it matters:** DPI and multi-monitor errors are the main way capture tools break. ShareX users are unsettled right now. A Snip proven on mixed-DPI setups is something Lens can claim, and a cheap one.
- **Lens status:** **Partial.**
  - `snip/geom.rs` handles per-monitor DPI.
  - The robustness wave (#119) fixed multi-monitor DPI for the Dock and Top Bar.
  - There is no Snip E2E on a 100 % + 150 % layout or on negative-coordinate monitors, and no overlay frame-time or memory budget.
- **Effort / risk:** S–M / low.
- **Files likely touched:** `src-tauri/src/snip/geom.rs` (property tests for negative origins and mixed scale), `tests/e2e/` (a new Snip overlay scenario), `docs/PERF_REPORT.md` (overlay budget).

### 4. Live text "Copy as table" and "Join lines"
- **Evidence:**
  - Windows Snipping Tool's Text Extractor offers "copy as table" ([WindowsForum](https://windowsforum.com/news/windows-11-snipping-tool-a-native-all-in-one-visual-toolkit.392881/); background, Dec 2025).
  - Snagit 2026.4 made Microsoft OCR the default for Grab Text ([release notes](https://download.techsmith.com/update/snagit/enu/26_updatemessage.html); undated).
  - People asked for OCR on Product Hunt captures (KlyxShot, AuroShot; months old).
- **Why it matters:** Snip live text shipped in #136, so these are the next small step. Tables in screenshots (invoices, dashboards, spec sheets) are where people retype the most.
- **Lens status:** **Partial.**
  - Live text and OCR exist (`src/snip/liveText.ts`, `src-tauri/src/snip/ocr.rs`).
  - Selected text joins words with spaces and lines with line breaks (`liveText.ts:187`).
  - There is no table or column grouping and no "join lines".
- **Effort / risk:** S for join lines, M for tables (cluster OCR word boxes into columns by x overlap, then emit TSV or Markdown) / low.
- **Files likely touched:** `src/snip/liveText.ts`, `src/snip/Studio.tsx`, `src/snip/actions.ts`, the unit tests beside `liveText.ts`.

### 5. Snip editor polish: saved colours, and numbered steps that can start at any number
- **Evidence:**

- **Lens status:** **Partial.**

  - There are no saved colour swatches beyond the theme accent.
- **Effort / risk:** S / low.
- **Files likely touched:** `src/snip/annotations.ts`, `src/snip/Studio.tsx`, `src-tauri/src/snip/config.rs` (saved colours, last step number), `src/snip/snip.css`.

## 6. Long-term bets

1. **One Windows.Graphics.Capture pipeline for Snip.** HDR-correct stills, recording without FFmpeg, and per-window capture while covered. This joins idea 1 and backlog #21.
2. **Snip as an input to agents:** a dictated caption, plus OCR text, plus the image as one context pack for Claude or MCP (ideas 2 and 4). Image transfer should follow the MCP upload/download draft once it settles.
3. **Proven reliability as a feature.** Published DPI, multi-monitor and frame-time budgets for every Lens overlay (Snip, Dock, Top Bar), checked in CI. This answers the regression fatigue ShareX users are showing.
