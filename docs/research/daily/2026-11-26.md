### 2. "Watch this page" in Lens Browser: local change checks with a Lens notification
- **Evidence:**
  - Firefox Smart Window gained `/watch` (27 Oct): daily or weekly checks of up to 5 pages for prices, stock or job posts, with desktop notifications and opt-in only ([9to5Mac](https://9to5mac.com/2026/10/27/firefoxs-ai-powered-smart-window-gets-form-autofill-and-website-monitoring/)).
  - Raycast 2.14 (25 Nov) has AI read tabs and history through its browser extension ([Raycast changelog](https://raycast.com/changelog/windows)).
- **Why it matters:** "Tell me when this changes" is the most-cited everyday agent use for a browser. Lens can do it without a cloud model. It would check the readable text, or one picked element, and post a Lens bottom-right notification. AI would be optional, only to judge "is this the change I asked for".
- **Lens status:** **Missing.** Feeds (`src-tauri/src/feeds/`) polls official APIs and RSS only. Lens Browser has `pageRead("readable")` but no scheduled checks. No in-flight branch has it (the `/watch` hits are YouTube URLs).
- **Effort / risk:** M / medium.
  - Respect the rate limiter in `feeds/ratelimit.rs`, and only check while Lens runs.
  - Never send cookies to background checks. Run them in a cookieless or ephemeral profile, or clearly ask.
  - Cap at 15 watches.
- **Files likely touched:**
  - New `src-tauri/src/browser/watch.rs`
  - `src-tauri/src/feeds/ratelimit.rs` (reuse)
  - `src/browser/BrowserSurface.tsx` (context action), `src/context/actions.catalog.json` (new `watch_page` action)
  - Notifications through the existing `notify` path
  - `docs/LENS_BROWSER.md`

### 4. Explorer menu: catch up with Windows 11's new "Customize menu"
- **Evidence:**
  - The optional update KB5127936 (28 Oct; builds 26200/26300.9818) is rolling out a right-click "Customize menu" page. It can turn built-in commands off and show labels instead of icons. It can also put app extensions in the main menu or a submenu, or hide them ([TechRepublic, 4 Nov](https://www.techrepublic.com/article/news-windows-11-right-click-menu-controls/), [Insider blog, 17 Aug](https://blogs.windows.com/windows-insider/2026/08/17/improving-file-explorer-context-menu-faster-simpler-and-more-customizable/)).
  - Neither source says whether classic registry verbs are covered.
- **Why it matters:** Lens's Explorer verbs (#84) are classic registry verbs, so on Windows 11 they appear only under "Show more options". People on the new build will look in "Customize menu" for Lens and not find it, or will hide "app extensions" and think Lens broke.
- **Lens status:** **Partial.**
  - `docs/RIGHTCLICK.md:161` explains the compact-menu limit and the sparse-package plan, which is blocked on signing.
  - Settings tells people where to find the classic menu, but doesn't know about the new page.
- **Effort / risk:** S / low for the copy. Testing on a 9818 build tells whether classic verbs show up in the new page; L for the signed `IExplorerCommand` handler, which is still blocked.
- **Files likely touched:** the Connections → File Explorer card (`bridge` commands and its Settings card), `docs/RIGHTCLICK.md`, and `src-tauri/src/bridge/manifest.rs` only if the build check needs data.
