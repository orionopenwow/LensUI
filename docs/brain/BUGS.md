## Checked and fine

- `feeds/xml.rs` unwraps: the stack always keeps the `#document` root (`pos == 0` is skipped), so the pops can't fail on hostile feeds; depth and node caps bound memory.
- Every `remove_dir_all`/`remove_file` in Rust: paths come from `config_dir()`, validated ids (`is_scene_id`, `plugin_dir`, `theme_path`), or Lens-owned temp files. `delete_lens_data` refuses a folder not ending in `LensUI`. `remove_plugin` handles symlinks without following them.
- `setInterval` and `addEventListener` sites all have matching clears/removes, except the two global error handlers in `main.tsx` and the plugin SDK's `message` listener, which live for the window's lifetime by design.
- `title=` hits on `<Section title=…>` are component props; `iframe title` is an accessible name, not a tooltip.
- Crash path: panic hook writes a scrubbed report; taskbar restore runs from the console handler and restore scripts.
- Remove all also covers: Lens at work (presence keeps only `%APPDATA%` settings and overlays that close with Lens), Feeds (no OS change), Messages toast mirroring (reads notifications, writes nothing to Windows), Lens Apps installs (apps the person installed are theirs; see B-08 for recipes).
